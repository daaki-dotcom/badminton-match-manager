## 1. データ同期設計（useFirebase フック）

### 1-1. リアルタイム同期の仕組み

```
[Firebase Realtime DB]
        │
        │ onValue()（WebSocket で常時監視）
        ▼
[useFirebase フック]
        │ setState() で React の状態を更新
        ▼
[React 再レンダリング → 全員の画面に即時反映]

        ↑
        │ fbSet / fbUpdate（データ書き込み）
        └──────────── [各コンポーネントのハンドラ]
```

### 1-2. 書き込み競合の防止

Firebase は自分が書き込んだデータも `onValue` で受信するため、書き込み中に受信データで上書きされないよう `writeCount` で制御します。

```
fbSet / fbUpdate 呼び出し時:
  1. writeCount++ （書き込み開始を記録）
  2. await set() / update() （Firebase に書き込む）
  3. writeCount-- （書き込み完了）

onValue コールバック内:
  writeCount > 0 の場合 → 受信データを無視する
  writeCount === 0 の場合 → 受信データで状態を更新する
```

### 1-3. 自動リセットロジック

ゲストの出欠データ・活動日・懇親会データを活動日の7日後に自動クリアします。

```
onValue でデータを受信するたびに以下を判定:

activityDate が空でない場合:
  deadline = new Date(activityDate)
  deadline.setDate(deadline.getDate() + 7)

  new Date() > deadline の場合:
    → fbSet('badminton/attendance', {})  ← 全出欠クリア
    → fbSet('badminton/activityDate', '') ← 活動日クリア
    → fbSet('badminton/party', {})       ← 懇親会クリア
    ※ memberLevels・courts・matches はリセット対象外
```

## 2. 試合組み合わせ生成アルゴリズム

### 2-1. フェーズ構造（共通）

全試合形式に共通するフェーズ構造です。各フェーズでは「現フェーズの最低出場回数に達していないメンバー」を優先して出場させます。

| フェーズ | 条件 |
|---------|------|
| フェーズ1 | 全員が最低1試合出場するまで生成 |
| フェーズ2 | 全員が最低2試合出場するまで生成 |
| フェーズ3 | 全員が最低3試合出場するまで生成 |
| フェーズ4 | 全員が最低4試合出場するまで生成 |

### 2-2. シングルス生成（generateSingles）

**目的:** 出席メンバー全員が均等に対戦できる組み合わせを生成する

**処理フロー:**
```
1. 全対戦候補をリストアップ（N人から C(N,2) = N*(N-1)/2 通り）

2. 目標試合数を計算
   - 1人あたり N 試合指定 → 総試合数 = ceil(N人 × N試合 ÷ 2)
   - 合計 M 試合指定 → 総試合数 = M
   - 指定しない → 総当たり全組み合わせで終了

3. ラウンド単位で試合を選択（1ラウンド = コート数分の試合）
   以下の3パスを順に試みる:

   パス1: 連続不可 + 均等 + 同ラウンド重複なし
     → 直前ラウンド出場者を除外
     → minCount（最小出場数）に達していない人を優先
     → 同ラウンドで同じ人を複数試合に出場させない

   パス2: 連続不可を緩和（均等 + 同ラウンド重複なしのみ）
     → パス1で必要数が埋まらない場合

   パス3: 均等も緩和（同ラウンド重複なしのみ）
     → パス2でも埋まらない場合

4. 生成された試合にコート番号を割り当てる（1番から順番に）
```

**同じペアが直前ラウンドと連続しないルール:**  
（トグル設定に関係なく常に適用）
```
prevRound の試合ペア一覧を取得
今回選ぼうとしている対戦が prevRound に含まれる場合 → スキップ
```

**均等にするルール:**
```
各プレイヤーの現在の試合数を集計 → minCount = 最小値
選ぼうとしている対戦の両プレイヤーが minCount より大きい場合 → スキップ
```

### 2-3. ダブルス生成（generateDoubles）

**目的:** 4人1組のダブルス試合を均等なペアで生成する

**処理フロー:**
```
1. 出場候補からフェーズ条件を満たす4人を選択
   フェーズ1（全員が1試合未満）の場合: まだ0試合の人を優先

2. 4人から3通りのペア組み合わせを評価
   パターンA: [0,1] vs [2,3]
   パターンB: [0,2] vs [1,3]
   パターンC: [0,3] vs [1,2]

3. 各パターンに対して条件チェック
   フェーズ1: 2人のペアが一度も組んだことがない → 有効
   フェーズ2以降: 直前ラウンドと同じペアでない → 有効
   （連続不可トグルに従い、4人全員が直前ラウンド出場者でないことも確認）

4. 有効なパターンのうち、ペア使用回数の合計が最少のものを選択
   → 同数の場合はランダムに選択

5. コート番号を割り当てる（1番から順番に）
```

### 2-4. 連続不可の自動緩和（フェーズ2実装）

人数が少なく連続不可を守ると試合が生成できない場合に自動で緩和します。

```
shouldRelaxConsec(pool, courts, prevRound) の判定:

シングルスの場合:
  1ラウンドの出場人数 = courts × 2
  待機可能人数 = pool.length - 1ラウンド出場人数
  待機可能人数 < 連続不可除外人数 の場合 → 緩和（警告なし）

ダブルスの場合:
  1ラウンドの出場人数 = courts × 4
  残り人数 = pool.length - 1ラウンド出場人数
  残り人数 < 4（ダブルスに必要な最低人数）の場合 → 緩和（警告なし）
```

**具体例:**
```
シングルス / コート3面 / 参加者7人:
  1ラウンド出場 = 6人、残り = 1人
  1人では連続不可を守れない → 自動緩和

ダブルス / コート3面 / 参加者14人:
  1ラウンド出場 = 12人、残り = 2人
  2人ではダブルス不可（4人必要）→ 自動緩和
```

## 3. 権限管理設計

### 3-1. フェーズ1（現行：パスワード認証）

```
変更（全体）が必要な操作（活動日設定・リセット等）:
  → パスワード入力モーダルを表示
  → 入力値 === ADMIN_PW（firebase.ts に定義）の場合に操作を実行
```

**現状の問題点:**
- パスワードがビルド成果物に含まれる（難読化はされるが逆コンパイル可能）
- 認証状態が維持されない（操作ごとにパスワード入力が必要）
- 4段階権限を表現できない

### 3-2. フェーズ2（Firebase Authentication 連携）

**認証フロー:**
```
[ログイン画面]
  → ランダムID + パスワード入力
  → signInWithEmailAndPassword(auth, `${randomId}@badminton.app`, password)
  → 成功: onAuthStateChanged で uid を取得
  → users/{randomId}/uid と照合して権限を確認

初回ログイン:
  → users/{randomId}/isFirstLogin === true の場合
  → パスワード変更強制画面へリダイレクト
  → updatePassword() でパスワードを変更
  → isFirstLogin を false に更新
```

**Firebase Database Rules（フェーズ2）:**
```json
{
  "rules": {
    "badminton": {
      ".read": true,
      "matches": {
        ".write": "auth != null && root.child('badminton/users').child(auth.token.email.split('@')[0]).child('role_edit').val() === true"
      },
      "memberLevels": {
        ".write": "auth != null && root.child('badminton/users').child(auth.token.email.split('@')[0]).child('role_edit').val() === true"
      },
      "users": {
        ".write": "auth != null && root.child('badminton/users').child(auth.token.email.split('@')[0]).child('role_admin').val() === true"
      }
    }
  }
}
```
