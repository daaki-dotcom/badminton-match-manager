# コーディング規約

## バドミントン試合管理ツール

**バージョン:** 2.0  
**作成日:** 2026-05-07

---

## 1. 基本方針

- TypeScript の型を必ず定義する（`any` は禁止）
- 関数は1つの責務だけ持つ（長くなったら分割する）
- コメントは「なぜそうするか」を書く（何をしているかはコードが示す）
- ファイル1つ = コンポーネント1つ（1ファイルに複数コンポーネントを詰め込まない）
- コードは英語で記述し、コメント・説明文は日本語で記述する

## 2. ファイル・フォルダ命名規則

| 種別 | 命名規則 | 例 |
|------|---------|-----|
| コンポーネント | PascalCase | `Attendance.tsx`, `Header.tsx` |
| カスタムフック | camelCase（`use` 接頭辞） | `useFirebase.ts` |
| 型定義ファイル | camelCase | `types.ts` |
| ユーティリティ | camelCase | `algorithm.ts` |
| スタイル | camelCase | `index.css` |
| 設計書 | 番号+日本語 | `01_システム構成図.md` |

## 3. TypeScript

```typescript
// ✅ 良い例: 型を明示する
const [matchType, setMatchType] = useState<MatchType>('singles')

// ❌ 悪い例: any を使う
const [matchType, setMatchType] = useState<any>('singles')

// ✅ 良い例: ユニオン型で値を制限する
type AttendanceStatus = 'yes' | 'no' | 'undecided' | ''

// ✅ 良い例: Props に interface を使う
interface Props {
  attendance: Record<string, AttendanceStatus>
  onSubmit: (name: string, val: AttendanceStatus) => void
}

// ✅ 良い例: 型エクスポートは types.ts に集約する
export type { AttendanceStatus, MemberLevel, Match }

// ❌ 悪い例: 各コンポーネント内に型をバラバラに定義する
```

## 4. React コンポーネント

```typescript
// ✅ 良い例: 関数コンポーネント + named export
export function Attendance({ attendance, onSubmit }: Props) {
  return <div>...</div>
}

// ❌ 悪い例: default export（import 時に名前が変わる危険がある）
export default function Attendance() { ... }

// ✅ 良い例: 早期 return で条件分岐のネストを浅くする
if (loading) return <div className="loading">接続中...</div>
return <div>...</div>

// ❌ 悪い例: ネストが深い条件分岐
return (
  <div>
    {loading ? <div>接続中...</div> : (
      <div>{/* 深いネスト */}</div>
    )}
  </div>
)

// ✅ 良い例: JSX の条件表示は && または 三項演算子を使う
{isAdmin && <button onClick={handleReset}>リセット</button>}
{error ? <p className="error">{error}</p> : null}
```

## 5. 状態管理

```typescript
// ✅ 良い例: setState は前の状態を参照する関数形式を使う
setState(prev => ({ ...prev, courts: 3 }))

// ❌ 悪い例: クロージャで古い状態を参照する
setState({ ...state, courts: 3 })

// ✅ 良い例: Firebase 書き込みは fbSet / fbUpdate を使う（直接 SDK を呼ばない）
fbSet('badminton/attendance', next)

// ❌ 悪い例: コンポーネント内で直接 Firebase SDK を呼ぶ
set(ref(db, 'badminton/attendance'), next)

// ✅ 良い例: 書き込み後に setState を呼ぶ順序を守る
await fbSet('badminton/matches', newMatches)
// 状態は Firebase からの onValue で自動更新されるため、手動 setState は不要
```

## 6. イベントハンドラの命名

| パターン | 命名規則 | 例 |
|---------|----------|-----|
| コンポーネント内ハンドラ | `handle` + 動作名（動詞） | `handleSubmit`, `handleReset` |
| Props として受け取るコールバック | `on` + 動作名 | `onSubmit`, `onReset` |

```typescript
// ✅ 良い例
// コンポーネント内
const handleSubmit = () => { ... }
<button onClick={handleSubmit}>登録</button>

// App から子へ Props 渡し
<Attendance onSubmit={handleSubmitAttendance} />

// ❌ 悪い例: 命名が統一されていない
const submitHandler = () => { ... }
<Attendance submit={submitHandler} />
```

## 8. Firebase パス

```typescript
// ✅ 良い例: パスは定数として管理する（firebase.ts で定義）
export const ROOT = 'badminton'
fbSet(`${ROOT}/attendance`, data)

// ❌ 悪い例: パスをコンポーネント内でハードコードする
fbSet('badminton/attendance', data)
```

## 9. 禁止事項

| 禁止 | 理由 | 代替手段 |
|------|------|---------|
| `any` 型 | TypeScript の型安全の恩恵を失う | 適切な型・ジェネリクスを定義する |
| `console.log` を残す | 本番環境で情報が漏れる | 開発時のみ使用し、コミット前に削除する |
| `alert()` / `confirm()` | ブラウザ依存・UX が悪い | カスタムモーダルコンポーネントを使う |
| ハードコードされたパスワード | セキュリティリスク（ビルド成果物に含まれる） | フェーズ2 で Firebase Authentication に移行 |
| コンポーネント内で直接 Firebase SDK を呼ぶ | useFirebase フックで一元管理するため | `fbSet` / `fbUpdate` を使う |
| `export default` | 名前の衝突・リファクタリング困難 | `export function` の named export を使う |

## 10. コミットメッセージ

```
種別: 内容の要約（50文字以内が目安）

種別の一覧:
  feat     新機能の追加
  fix      バグ修正
  refactor 動作を変えないコード整理
  docs     ドキュメントのみの変更
  style    デザイン・見た目の変更
  chore    設定ファイル・依存パッケージの更新

例:
  feat: 懇親会タブにリセット機能を追加
  fix: ダブルス生成時の無限ループを修正
  refactor: Matches コンポーネントをサブコンポーネントに分割
  docs: 詳細設計書のアルゴリズム説明を更新
```

## 11. ディレクトリ構成規約

```
src/
├── types.ts           ← 全型定義（各コンポーネントが import する）
├── algorithm.ts       ← 試合生成ロジック（UI 依存なし）
├── firebase.ts        ← Firebase 初期化・設定
├── main.tsx           ← エントリポイント
├── App.tsx            ← ルートコンポーネント・ハンドラ定義
│
├── hooks/
│   └── useFirebase.ts ← Firebase 同期フック
│
├── components/
│   ├── Header.tsx
│   ├── Attendance.tsx
│   ├── Members.tsx
│   ├── Matches.tsx
│   ├── Results.tsx
│   └── Party.tsx
│
└── styles/
    └── index.css
```

新しいコンポーネントは `src/components/` に、新しいフックは `src/hooks/` に配置する。
