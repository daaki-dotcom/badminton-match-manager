# テーブル定義書（データ定義書）

## バドミントン試合管理ツール

**バージョン:** 2.0  
**作成日:** 2026-05-07

---

## 概要

Firebase Realtime Database は JSON ツリー構造のため、従来の RDB テーブル定義の代わりに  
**ノード定義書**として各データの型・制約・用途を記述します。

---

## フェーズ1 ノード定義

### 1. attendance（出欠）

**パス:** `badminton/attendance`  
**型:** `Record<string, AttendanceStatus>`  
**説明:** メンバー（正規部員・ゲスト）ごとの出欠状況を管理する

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| キー（名前） | string | 任意の文字列 | ✅ | 正規部員名 または「ゲスト_〇〇」形式 |
| 値（出欠状態） | string | `"yes"` / `"no"` / `"undecided"` / `""` | ✅ | 参加・不参加・未定・未回答 |

**制約:**
- キーは空文字不可
- ゲストは `"yes"` のみ設定可能（不参加・未定は不要）
- 正規部員の出欠データはリセット対象外（活動日をまたいで保持）
- ゲストの出欠データは活動日から7日後に自動クリア

---

### 2. memberLevels（メンバーレベル）

**パス:** `badminton/memberLevels`  
**型:** `Record<string, MemberLevel>`  
**説明:** 参加者ごとのレベル（経験者・未経験者）を管理する

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| キー（名前） | string | 任意の文字列 | ✅ | attendance と同一のキー |
| 値（レベル） | string | `"exp"` / `"nov"` | ✅ | 経験者 / 未経験者 |

**制約:**
- 値は `"exp"` または `"nov"` のみ
- 未設定の場合はデフォルト `"nov"`（未経験者）扱い
- リセット対象外（開催をまたいで保持）

---

### 3. activityDate（活動日）

**パス:** `badminton/activityDate`  
**型:** `string`  
**説明:** 次回活動日を管理する。ゲストデータの自動リセット基準日

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| activityDate | string | `"YYYY-MM-DD"` / `""` | - | 活動日。未設定時は空文字 |

**制約:**
- ISO 8601 形式（例: `"2026-05-10"`）
- 変更（全体）権限を持つ正規部員のみ設定可能
- 活動日 + 7日後に自動クリア

---

### 4. courts（コート数）

**パス:** `badminton/courts`  
**型:** `number`  
**説明:** 使用するコート数を管理する

| フィールド | 型 | デフォルト | 最小値 | 最大値 | 説明 |
|-----------|----|-----------  |--------|--------|------|
| courts | number | `2` | `1` | `20` | コート数（整数） |

**制約:**
- 1以上20以下の整数
- 変更（全体）権限を持つ正規部員のみ変更可能

---

### 5. matches（試合）

**パス:** `badminton/matches`  
**型:** `Match[]`（Firebase 上は 0 始まりのインデックスをキーとするオブジェクト）  
**説明:** 生成された試合の一覧を管理する

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| p1 | string | 名前 or `"A / B"` | ✅ | プレイヤー1（ダブルスはスラッシュ区切りのペア名） |
| p2 | string | 名前 or `"C / D"` | ✅ | プレイヤー2（ダブルスはスラッシュ区切りのペア名） |
| s1 | string | 数字文字列 / `""` | - | p1 側スコア（未入力は空文字） |
| s2 | string | 数字文字列 / `""` | - | p2 側スコア（未入力は空文字） |
| status | string | `"wait"` / `"playing"` / `"done"` | ✅ | 待機中・試合中・終了 |
| court | number | 1以上の整数 | ✅ | 割り当てられたコート番号 |

**制約:**
- p1・p2 は空文字不可
- s1・s2 は 0〜99 の数値（文字列として保持）
- status は 3 種類のみ
- リセット時にノードごと削除する

---

### 6. party（懇親会）

**パス:** `badminton/party`  
**型:** `Record<string, PartyStatus>`  
**説明:** 懇親会の参加意向を管理する

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| キー（名前） | string | 任意の文字列 | ✅ | attendance と同一のキー |
| 値（参加状態） | string | `"yes"` / `"no"` / `""` | ✅ | 参加・不参加・未回答 |

**制約:**
- 参加者（出欠が `"yes"` の人）のみ登録可能
- 活動日から7日後に自動クリア

---

## フェーズ2 追加ノード定義

### 7. users（正規部員マスタ）

**パス:** `badminton/users`  
**型:** `Record<string, User>`  
**説明:** 正規部員のアカウント情報・権限を管理する（フェーズ2実装）

| フィールド | 型 | 値 | 必須 | 説明 |
|-----------|----|----|------|------|
| キー（ランダムID） | string | ランダムな英数字 | ✅ | システムが自動発行するID（ユーザーに通知） |
| name | string | 任意の文字列 | ✅ | 正規部員の名前 |
| uid | string | Firebase UID | ✅ | Firebase Authentication の UID と紐付け |
| role_edit | boolean | `true` / `false` | ✅ | 変更（全体）権限の有無 |
| role_admin | boolean | `true` / `false` | ✅ | 登録権限の有無 |
| isFirstLogin | boolean | `true` / `false` | ✅ | 初回ログイン済みフラグ（`true` = 未変更） |

**制約:**
- `role_admin: true` は登録権限を持つ正規部員のみが付与可能
- ランダムID は `ランダムID@badminton.app` として Firebase Authentication に登録する

## TypeScript 型定義（types.ts）

```typescript
// 出欠状態
type AttendanceStatus = 'yes' | 'no' | 'undecided' | ''

// メンバーレベル
type MemberLevel = 'exp' | 'nov'

// 試合ステータス
type MatchStatus = 'wait' | 'playing' | 'done'

// 試合形式
type MatchType = 'singles' | 'doubles'

// 対象フィルター
type TierFilter = 'all' | 'exp' | 'nov'

// 懇親会参加状態
type PartyStatus = 'yes' | 'no' | ''

// 試合1件
interface Match {
  p1: string       // プレイヤー1（ダブルスは "A / B" 形式）
  p2: string       // プレイヤー2（ダブルスは "C / D" 形式）
  s1: string       // p1 側スコア（未入力は ""）
  s2: string       // p2 側スコア（未入力は ""）
  status: MatchStatus
  court: number
}

// アプリ全体の状態
interface AppState {
  attendance: Record<string, AttendanceStatus>
  memberLevels: Record<string, MemberLevel>
  activityDate: string
  courts: number
  matches: Match[]
  party: Record<string, PartyStatus>
}

// フェーズ2: 正規部員
interface User {
  name: string
  uid: string
  role_edit: boolean
  role_admin: boolean
  isFirstLogin: boolean
}
```
