## 3. データフロー

```
[ユーザー操作]
    │
    ▼
[React コンポーネント]
    │ イベントハンドラ呼び出し
    ▼
[useFirebase カスタムフック]
    │ fbSet / fbUpdate（Firebase SDK）
    ▼
[Firebase Realtime Database]
    │ onValue（リアルタイム受信）
    ▼
[全接続クライアントに即時反映]
    │ 状態更新 → 再レンダリング
    ▼
[React コンポーネント（全員の画面が自動更新）]
```

**ポイント：**  
Firebase Realtime Database の WebSocket 通信により、幹事がスコアを入力すると全メンバーの画面に即座に反映されます（ポーリング不要）。

---

## 4. 権限設計

| 権限レベル | 対象 | できること |
|-----------|------|-----------|
| 閲覧 | 全員（未ログイン・ゲスト含む） | 全タブの閲覧 |
| 変更（個人） | ログイン済みの正規部員 | 自分の出欠回答・懇親会回答・パスワード変更 |
| 変更（全体） | 限られた正規部員 | 全員の出欠・ゲスト削除・試合状況・スコア・活動日設定・メンバーのレベル設定 |
| 登録 | 限られた正規部員 | 正規部員の追加・削除・権限付与 |

## 5. 開発フェーズ

| フェーズ | 内容 | 状態 |
|---------|------|------|
| フェーズ1 | 出欠管理・試合組み合わせ生成・スコア管理・結果集計・懇親会管理 | 実装済み |
| フェーズ2 | Firebase Authentication によるログイン・アカウント管理・連続不可の自動緩和 | 開発予定 |

## 7. 非機能要件

| 項目 | 要件 |
|------|------|
| 対応デバイス | スマートフォン中心（iPhone / Android）、PC対応 |
| 対応ブラウザ | Chrome・Safari 最新版 |
| 想定利用人数 | 最大30人 / 開催あたり6〜30人 |
| 通信方式 | Firebase WebSocket（リアルタイム同期） |
| データ保持 | ゲストの出欠データは活動日から7日後に自動リセット |
