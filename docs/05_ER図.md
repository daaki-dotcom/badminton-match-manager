# ER図

## バドミントン試合管理ツール

**バージョン:** 2.0  
**作成日:** 2026-05-07

---

## 概要

このシステムは Firebase Realtime Database（JSON ツリー構造）を使用しています。  
リレーショナル DB（テーブル間の外部キー結合）とは異なり、**JSON の階層構造でデータを管理**します。  
フェーズ2 では Firebase Authentication によるユーザー管理が追加されます。

---

## 1. フェーズ1 データ構造図

```
badminton/                              ← ルートノード
│
├── activityDate: "2026-05-10"          ← 活動日（YYYY-MM-DD 形式）
│
├── courts: 2                           ← コート数（数値）
│
├── attendance/                         ← 出欠データ
│   ├── "山田太郎":   "yes"             ← 参加
│   ├── "鈴木花子":   "no"              ← 不参加
│   ├── "田中一郎":   "undecided"       ← 未定
│   └── "ゲスト_佐藤": "yes"            ← ゲスト（参加のみ）
│
├── memberLevels/                       ← メンバーレベル（参加者全員）
│   ├── "山田太郎":   "exp"             ← 経験者
│   ├── "鈴木花子":   "nov"             ← 未経験者
│   └── "ゲスト_佐藤": "nov"
│
├── matches/                            ← 試合データ
│   ├── 0/
│   │   ├── p1:     "山田太郎"          ← プレイヤー1（ダブルスは "A / B" 形式）
│   │   ├── p2:     "鈴木花子"          ← プレイヤー2（ダブルスは "C / D" 形式）
│   │   ├── s1:     "21"               ← p1 側スコア
│   │   ├── s2:     "15"               ← p2 側スコア
│   │   ├── status: "done"             ← wait / playing / done
│   │   └── court:  1                  ← コート番号（1〜）
│   └── 1/ ...
│
└── party/                              ← 懇親会参加データ
    ├── "山田太郎": "yes"               ← 参加
    ├── "鈴木花子": "no"                ← 不参加
    └── "田中一郎": ""                  ← 未回答
```

## 2. フェーズ1 エンティティ関係図

```
┌──────────────────────┐       ┌────────────────────┐
│  activityDate（活動日）│       │  courts（コート数）  │
│ ──────────────────── │       │ ────────────────── │
│  value: string        │       │  value: number      │
└──────────────────────┘       └────────────────────┘

┌──────────────────────┐
│  attendance（出欠）   │  ←  正規部員 or ゲストが1レコード持つ
│ ──────────────────── │
│  key:   string（名前）│
│  value: "yes" | "no" │
│         | "undecided"│
│         | ""         │
└────────┬─────────────┘
         │ 参加（yes）したメンバーが
         │ ↓ 試合・懇親会の対象になる

┌────────┴─────────────┐       ┌────────────────────┐
│  matches（試合）      │       │  party（懇親会）    │
│ ──────────────────── │       │ ────────────────── │
│  key:    number（連番）│       │  key:   string（名前）│
│  p1:     string       │       │  value: "yes" | "no"│
│  p2:     string       │       │         | ""        │
│  s1:     string       │       └────────────────────┘
│  s2:     string       │
│  status: string       │
│  court:  number       │
└──────────────────────┘

┌──────────────────────┐
│  memberLevels（レベル）│  ←  出欠登録した全員が持つ
│ ──────────────────── │
│  key:   string（名前）│
│  value: "exp" | "nov"│
└──────────────────────┘
```

## 3. フェーズ2 追加エンティティ図（認証実装後）

```
badminton/
│
├── ...（フェーズ1 と同様）
│
└── users/                              ← 正規部員マスタ（フェーズ2追加）
    ├── "ランダムID_abc1"/
    │   ├── name:        "山田太郎"
    │   ├── uid:         "Firebase UID"  ← Authentication の UID と紐付け
    │   ├── role_edit:   true            ← 変更（全体）権限
    │   ├── role_admin:  true            ← 登録権限
    │   ├── level:       "exp"
    │   └── isFirstLogin: false         ← 初回ログイン済みフラグ
    └── "ランダムID_def2"/
        ├── name:        "鈴木花子"
        ├── uid:         "Firebase UID"
        ├── role_edit:   true
        ├── role_admin:  false
        ├── level:       "nov"
        └── isFirstLogin: true          ← まだパスワード変更していない
```

## 4. 設計上の注意点

| 項目 | フェーズ1（現状） | フェーズ2（予定） |
|------|-----------------|-----------------|
| メンバーマスタ | なし（attendance/memberLevels のキーがメンバーリスト） | users/ ノードに正規部員マスタを追加 |
| 権限管理 | ハードコードされたパスワード | Firebase Authentication + users/ ノードで管理 |
| ゲスト削除 | 全リセットのみ | 個別削除（変更全体権限）で対応 |
| 開催履歴 | なし（7日後に自動リセット） | 将来的に開催ごとにデータを保存する構造へ |
| 連続不可の自動緩和 | 未実装 | フェーズ2 でアルゴリズムに組み込む |
