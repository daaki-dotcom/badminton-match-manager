# API仕様書

## バドミントン試合管理ツール

**バージョン:** 2.0  
**作成日:** 2026-05-07

---

## 概要

このシステムは独自の API サーバーを持たず、**Firebase SDK** を使ってデータの読み書きを行います。  
本書では Firebase Realtime Database・Authentication への操作を API 仕様として定義します。

**Firebase プロジェクト情報:**

| 項目 | 値 |
|------|---|
| プロジェクトID | `badminton-match-manager-e5ad8` |
| Realtime Database URL | `https://badminton-match-manager-e5ad8-default-rtdb.asia-southeast1.firebasedatabase.app` |
| ルートパス | `/badminton` |

---

## フェーズ1 API（Realtime Database）

### 共通仕様

| 項目 | 内容 |
|------|------|
| SDK | Firebase JavaScript SDK v10系 |
| 通信方式 | WebSocket（リアルタイム同期） |
| データ形式 | JSON |
| 内部関数 | `fbSet(path, value)` → `set(ref(db, path), value)` |
| 内部関数 | `fbUpdate(path, value)` → `update(ref(db, path), value)` |

---

### API-01 全データ リアルタイム監視

| 項目 | 内容 |
|------|------|
| 操作 | `onValue(ref(db, 'badminton'), callback)` |
| 説明 | アプリ全体のデータをリアルタイムで監視する |
| タイミング | アプリ起動時から常時接続 |
| 権限 | 全員（読み取りは制限なし） |

**返却データ構造:**
```json
{
  "activityDate": "2026-05-10",
  "courts": 2,
  "attendance": {
    "山田太郎": "yes",
    "鈴木花子": "no",
    "ゲスト_田中": "yes"
  },
  "memberLevels": {
    "山田太郎": "exp",
    "鈴木花子": "nov",
    "ゲスト_田中": "nov"
  },
  "matches": {
    "0": {
      "p1": "山田太郎",
      "p2": "鈴木花子",
      "s1": "21",
      "s2": "15",
      "status": "done",
      "court": 1
    }
  },
  "party": {
    "山田太郎": "yes",
    "鈴木花子": ""
  }
}
```

---

### API-02 出欠 全件更新

| 項目 | 内容 |
|------|------|
| 操作 | `fbSet('badminton/attendance', data)` |
| 説明 | 出欠データ全体を上書きする |
| 権限 | 全員（変更（個人）は自分のみ、変更（全体）は全員分） |

**送信データ例:**
```json
{
  "山田太郎": "yes",
  "鈴木花子": "no",
  "田中一郎": "undecided",
  "ゲスト_佐藤": "yes"
}
```

**AttendanceStatus の値:**

| 値 | 意味 |
|----|------|
| `"yes"` | 参加 |
| `"no"` | 不参加 |
| `"undecided"` | 未定 |
| `""` | 未回答 |

---

### API-03 活動日 設定

| 項目 | 内容 |
|------|------|
| 操作 | `fbSet('badminton/activityDate', "2026-05-10")` |
| 説明 | 活動日を設定する |
| 権限 | 変更（全体） |

**送信データ:** `"YYYY-MM-DD"` 形式の文字列（例: `"2026-05-10"`）

---

### API-04 コート数 更新

| 項目 | 内容 |
|------|------|
| 操作 | `fbSet('badminton/courts', 3)` |
| 説明 | コート数を更新する |
| 権限 | 変更（全体） |

**送信データ:** 1〜20 の整数

---

### API-05 メンバーレベル 個別更新

| 項目 | 内容 |
|------|------|
| 操作 | `fbUpdate('badminton/memberLevels', { "山田太郎": "exp" })` |
| 説明 | 特定メンバーのレベルのみ更新する（他は変更しない） |
| 権限 | 変更（全体） |

**送信データ例:**
```json
{ "山田太郎": "exp" }
```

**MemberLevel の値:**

| 値 | 意味 |
|----|------|
| `"exp"` | 経験者 |
| `"nov"` | 未経験者 |

---

### API-06 試合データ 全件保存

| 項目 | 内容 |
|------|------|
| 操作 | `fbSet('badminton/matches', data)` |
| 説明 | 組み合わせ生成後、試合データ全体を上書きする |
| 権限 | 変更（全体） |

**送信データ例:**
```json
{
  "0": { "p1": "山田太郎", "p2": "鈴木花子", "s1": "", "s2": "", "status": "wait", "court": 1 },
  "1": { "p1": "田中一郎", "p2": "佐藤二郎", "s1": "", "s2": "", "status": "wait", "court": 2 }
}
```

---

### API-07 試合 スコア・ステータス 個別更新

| 項目 | 内容 |
|------|------|
| 操作 | `fbUpdate('badminton/matches/0', { s1: "21", s2: "15", status: "done" })` |
| 説明 | 特定の試合のスコアおよびステータスを更新する |
| 権限 | 変更（全体） |

**送信データ例:**
```json
{
  "s1": "21",
  "s2": "15",
  "status": "done"
}
```

**MatchStatus の値:**

| 値 | 意味 |
|----|------|
| `"wait"` | 待機中 |
| `"playing"` | 試合中 |
| `"done"` | 終了 |

---

### API-08 懇親会 全件更新

| 項目 | 内容 |
|------|------|
| 操作 | `fbSet('badminton/party', data)` |
| 説明 | 懇親会参加データ全体を上書きする |
| 権限 | 変更（個人）は自分のみ、変更（全体）はリセット |

**送信データ例:**
```json
{
  "山田太郎": "yes",
  "鈴木花子": "no",
  "田中一郎": ""
}
```

## フェーズ2 API（Firebase Authentication）

### API-09 ログイン

| 項目 | 内容 |
|------|------|
| 操作 | `signInWithEmailAndPassword(auth, email, password)` |
| 説明 | ランダムID＋パスワードでログインする |
| メール形式 | `{ランダムID}@badminton.app` |
| 初回パスワード | `nicesoul`（全員共通、初回ログイン時に変更強制） |

---

### API-10 パスワード変更

| 項目 | 内容 |
|------|------|
| 操作 | `updatePassword(currentUser, newPassword)` |
| 説明 | ログイン中のユーザーのパスワードを変更する |
| 権限 | 正規部員（自分のパスワードのみ） |

---

### API-11 認証状態監視

| 項目 | 内容 |
|------|------|
| 操作 | `onAuthStateChanged(auth, callback)` |
| 説明 | ログイン状態を監視し、権限制御に使用する |
| タイミング | アプリ起動時から常時監視 |

---

### API-12 ログアウト

| 項目 | 内容 |
|------|------|
| 操作 | `signOut(auth)` |
| 説明 | セッションを終了する |
| 権限 | ログイン中の正規部員 |

---

## エラーハンドリング

| エラー種別 | 発生条件 | 対応 |
|-----------|---------|------|
| Firebase 接続失敗 | ネットワーク切断など | ヘッダーに「⚠ 切断中」を表示、操作はブロックしない |
| 書き込み競合 | 複数クライアントの同時書き込み | Firebase のリアルタイム同期が自動解決 |
| 認証エラー | パスワード不一致（フェーズ2） | モーダルにエラーメッセージを表示 |
| 権限不足 | Database Rules で拒否（フェーズ2） | エラートースト表示 |

## セキュリティ設計

| 項目 | フェーズ1（現状） | フェーズ2（予定） |
|------|-----------------|-----------------|
| Database Rules | 全読み書き許可（開発用） | Authentication 連携ルールに変更 |
| 管理者認証 | ハードコードパスワード | Firebase Authentication に移行 |
| API キー露出 | firebase.ts に直接記載（クライアント側） | Firebase のドメイン制限を設定して不正利用を防止 |
